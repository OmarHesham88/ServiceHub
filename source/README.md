# Al-Nakheel Residence 3D: handoff for another Claude

You are taking over a free-tools pipeline that turns building plans into:
1. Blender renders (3D floor plans, interiors, exteriors).
2. glTF models for the browser.
3. A one-page three.js viewer with 3 tabs: **العمارة كاملة** (whole building, orbit), **الدور المتكرر** (typical floor, orbit + room labels), **تمشّى جوه** (first-person walk from the street, into the lobby, up the stairs to the first floor).

Everything uses free software and CC0 assets. The current layout is a **placeholder**: it was reverse-engineered from a demo page's code (3 apartments per floor, proportion-based rooms). When the user sends real architect files (DWG/DXF/PDF), rebuild the layout from those files and keep the same pipeline.

## Files on this page

| File | What it is |
|---|---|
| `build3d_v2.py.txt` | **Main Blender script** (rename to `.py`). Builds geometry, materials, furniture, lights, cameras; renders images; exports glTF. |
| `fetch_assets.py.txt` | Downloads the CC0 textures and furniture models from Poly Haven into `assets/` (rename to `.py`). |
| `viewer-index.html.txt` | The full viewer page: HTML, CSS and a three.js module script (rename to `index.html`). |
| `rooms.json` | Room names, areas and label positions for the floor tab (generated by `rooms_json.py`). |
| `rooms_json.py.txt` | Regenerates `rooms.json` from the layout formulas. |
| `plan2d_gen.py.txt` | Draws the 2D typical-floor plan as SVG (Arabic labels; render with a browser). |
| `building-1.txt` | Whole-building GLB, **base64 text** (decode to get `building.glb`). |
| `typical-floor-1.txt` | Furnished typical floor GLB, base64. |
| `walk-1.txt`, `walk-2.txt` | Walkable model (site, lobby, stairs, 1 furnished floor) GLB, base64, split in two parts: concatenate, then decode. |

Decode a model: `cat walk-1.txt walk-2.txt | base64 -d > walk.glb`

## Environment setup (Linux, no GPU needed)

```bash
python3 -m venv venv
venv/bin/pip install bpy==5.3.0 pillow
python3 fetch_assets.py assets      # needs network access to api.polyhaven.com and dl.polyhaven.org
```

- Put `build3d_v2.py` in a folder next to `assets/` (the script looks for `assets/` beside itself).
- Poly Haven rejects Python's default User-Agent. `fetch_assets.py` already sends a browser-like one.
- Do not name any script `inspect.py`: it shadows the standard library and crashes `bpy` on import.

## Running the Blender jobs

```bash
venv/bin/python build3d_v2.py <outdir> <jobs> [samples]
```

`<jobs>` is a comma list:

| Job | Output |
|---|---|
| `plan` | `plan3d.png`: whole typical floor, cutaway (walls cut at 2.2 m) |
| `apt` | `apt1-3d.png`: apartment 1 cutaway |
| `interior` | `interior-living.png`: eye-level living room |
| `exterior` | `exterior-street.png`, `exterior-aerial.png` |
| `web` | `building.glb`, `typical-floor.glb` (textures shrunk to 512 px) |
| `walk` | `walk.glb` |

**Environment variables:**
- `LIGHT=1` simplifies heavy furniture (plants, chairs, lamps). Use it for every web export.
- `WALK_FLOORS=1` sets how many furnished floors the walk model has (default 1).

**Render speed:** Cycles runs on CPU only. 24 samples with OpenImageDenoise looks clean; 64 samples is slow (more than 10 minutes per image on 4 cores).

Typical commands:

```bash
LIGHT=1 WALK_FLOORS=1 venv/bin/python build3d_v2.py out walk,web
venv/bin/python build3d_v2.py out interior,apt,plan,exterior 24
```

## How the geometry works (build3d_v2.py)

- **Coordinates:** plan x is east, plan z is south, in metres. Blender uses X = x, Y = -z, Z = up. glTF comes out as (x, height, z), which is what the viewer uses.
- **Apartment layout:** `APTS` holds width, depth, bedroom count and window sides. `BACK` holds the back-room width fractions. `PLACE` holds the transforms that position and mirror the 3 apartments.
  - Rooms are derived from `zb = .42·D`, `xk = .62·W`, `zk = .72·D`, `xe = .8·W`.
  - Corridor: z 8.5 to 10.5. Stair core: x 11 to 15.
- **`MB` mesh builder:** collects axis-aligned boxes per material with box-mapped UVs in metres. Each material's tile size is in `TILE`. It emits one object per material.
- **Furniture:** `lib(name)` imports a Poly Haven glTF once, flattens it and optionally decimates it. `place(...)` adds linked duplicates, so the glTF stores each mesh only once.
  - Decimation must happen **before** the object is moved into the hidden `_lib` collection. Hidden objects are not evaluated by the depsgraph.
- **Stairs (walk model):** `stairs_walk()` builds a dog-leg stair. Flight A goes up the +z direction on x 11.1 to 12.9. The half landing is at z 17 to 18.5. Flight B returns on x 13.1 to 14.9. Steps are 10 × 0.16 m rise and 0.5 m tread, built as thin slabs. Floor slabs have a stair void at x 11 to 15, z 12 to 18.5, with rails.
- **Furniture grouping:** each floor's furniture is parented to an empty named `Furn <level>`, so the viewer can hide floors you are not on.

## How the viewer works (viewer-index.html)

- **Libraries:** three.js r160 via an importmap from cdn.jsdelivr.net (OrbitControls, GLTFLoader, RoomEnvironment).
- **Why models are base64 text:** the claude.ai artifact host only serves text, web image and font types, not `.glb`.
  - `load(name)` fetches the `name-N.txt` parts listed in `PARTS`, decodes them and calls `GLTFLoader.parse`.
  - On a normal web server, serve `.glb` files directly and use `loader.load()`. It is simpler and faster.
- **Walk mode:**
  - Controls: arrow keys or on-screen arrow pad, drag to look, tap the floor to walk there, speed slider.
  - Collision: horizontal raycasts at feet + 0.45 / 1.0 / 1.55 m, with the walker sliding along walls.
  - Ground: a downward raycast. Steps up to 0.32 m are climbed smoothly, and larger drops make you fall.
  - Movement runs in sub-steps of 0.03 s or less, so speed stays correct on slow devices.
- **Automatic tour:** `routeTour()` lists waypoints from the street, into the lobby, up both flights, to apartment 1 on the first floor. Height comes from the ground raycast automatically.
- **Room label:** `whereAmI()` maps a position and floor height to text such as "الدور الأول • شقة ١ • الريسيبشن".
